# Plan 04-01: Security Tweaks & Security Page

## Goal

Implement the Security page with 8 registry-based security toggles using the existing
`RegistryTweakService` + `TweakCatalog` + `TweakList` pattern. This is the **tracer slice**
for Phase 4 — a thin end-to-end path that proves the Security page works from registry read
to UI toggle.

**Decisions:** D-01 (RegistryTweakService + TweakCatalog for Security), D-02 (no WMI — registry only), D-05 (reuse Phase 3 elevation pattern), D-06 (TweakList for Security page)

## Requirements

| ID | Description |
|----|-------------|
| SEC-01 | Security page displays 8 toggles: Defender, Tamper Protection, VBS, Memory Integrity, Vulnerable Driver Blocklist, Spectre/Meltdown, UAC, SmartScreen |
| SEC-02 | Tamper Protection uses inverted values (5=on, 0=off) — toggle writes 0 to disable |
| SEC-03 | VBS and Memory Integrity indicate "reboot required" after applying |
| SEC-04 | UAC and SmartScreen show security warnings before applying |
| SEC-05 | All 8 Security tweaks write to HKLM and require admin elevation |

## must_haves

- D-01: Security toggles use RegistryTweakService + TweakCatalog (no new service)
- D-02: No WMI queries — registry only
- D-05: Reuse Phase 3 elevation pattern (IsElevated, applied vs reboot-required, RestartExplorerAsync)
- D-06: Security page uses TweakList control

## Research Notes

### Registry Paths (from 04-RESEARCH.md §1.1)

| ID | Hive | Key Path | Value Name | Enabled | Disabled | Default |
|----|------|----------|------------|---------|----------|---------|
| `security-defender-disable` | HKLM | `SOFTWARE\Policies\Microsoft\Windows Defender` | `DisableAntiSpyware` | 1 | 0 | 0 |
| `security-defender-tamper` | HKLM | `SOFTWARE\Microsoft\Windows Defender\Features` | `TamperProtection` | 0 | 5 | 5 |
| `security-vbs` | HKLM | `SYSTEM\CurrentControlSet\Control\DeviceGuard` | `EnableVirtualizationBasedSecurity` | 1 | 0 | 0 |
| `security-memory-integrity` | HKLM | `SYSTEM\CurrentControlSet\Control\DeviceGuard\Scenarios\HypervisorEnforcedCodeIntegrity` | `Enabled` | 1 | 0 | 0 |
| `security-vulnerable-driver-blocklist` | HKLM | `SYSTEM\CurrentControlSet\Control\CI\Config` | `VulnerableDriverBlocklistEnable` | 1 | 0 | 0 |
| `security-spectre-meltdown` | HKLM | `SYSTEM\CurrentControlSet\Control\Session Manager\Memory Management` | `FeatureSettingsOverride` | 0 | 3 | 0 |
| `security-uac` | HKLM | `SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System` | `EnableLUA` | 0 | 1 | 1 |
| `security-smartscreen` | HKLM | `SOFTWARE\Policies\Microsoft\Windows\System` | `EnableSmartScreen` | 0 | 1 | 1 |

### Key Observations

- **All 8 tweaks write to HKLM** → all require admin elevation (`RequiresAdmin = true`)
- **None require Explorer restart** — they are system-level, not shell-level
- **Tamper Protection is inverted**: `5` = enabled (on), `0` = disabled (off). The "Disable Tamper Protection" toggle writes `0` to disable it. `EnabledValue = 0`, `DisabledValue = 5`.
- **Spectre/Meltdown is inverted**: `FeatureSettingsOverride` value `3` = mitigations enabled (vulnerable), `0` = mitigations disabled (protected). The "Enable Spectre/Meltdown Mitigations" toggle writes `0` to enable protection. `EnabledValue = 0`, `DisabledValue = 3`.
- **UAC**: `EnableLUA` `1` = UAC enabled (default), `0` = UAC disabled. The "Disable UAC" toggle writes `0`. `EnabledValue = 0`, `DisabledValue = 1`.
- **SmartScreen**: `EnableSmartScreen` `1` = enabled (default), `0` = disabled. The "Disable SmartScreen" toggle writes `0`. `EnabledValue = 0`, `DisabledValue = 1`.
- **VBS/Memory Integrity**: Require reboot to take effect. The UI should indicate "reboot required" after applying.
- **Tamper Protection**: Windows 10/11 may prevent writing to this key even with admin rights. The UI should handle this gracefully.

## Design

### Architecture

This plan follows the exact same architecture as Phase 3's General/System pages:

1. **TweakCatalog** — static catalog of `RegistryTweak` definitions (data only)
2. **RegistryTweakService** — reads/writes registry values (already exists, no changes needed)
3. **TweakPageViewModel** — orchestrates load/toggle/revert/refresh for a page (already exists)
4. **TweakList** control — renders the UI (already exists)
5. **SecurityPage** — thin page that wires the factory to the control

No new services, no new ViewModels, no new controls. Pure data + wiring.

### Tweak Definitions

All 8 Security tweaks follow the `RegistryTweak` record pattern:

| Property | Value |
|----------|-------|
| `Hive` | `RegistryHive.LocalMachine` (all 8) |
| `RequiresAdmin` | `true` (all 8) |
| `RequiresExplorerRestart` | `false` (all 8) |
| `ValueKind` | `RegistryValueKind.DWord` (default, all 8) |
| `RemoveKeyWhenDisabled` | `false` (default, all 8) |

### Special Handling

- **Tamper Protection** (`security-defender-tamper`): `EnabledValue = 0`, `DisabledValue = 5`. The toggle name is "Disable Tamper Protection" — when the user enables this toggle, it writes `0` (disabling Tamper Protection). When the user disables this toggle, it writes `5` (re-enabling Tamper Protection).
- **Spectre/Meltdown** (`security-spectre-meltdown`): `EnabledValue = 0`, `DisabledValue = 3`. The toggle name is "Enable Spectre & Meltdown Mitigations" — when the user enables this toggle, it writes `0` (enabling mitigations). When the user disables this toggle, it writes `3` (disabling mitigations).
- **UAC** (`security-uac`): `EnabledValue = 0`, `DisabledValue = 1`. The toggle name is "Disable UAC" — when the user enables this toggle, it writes `0` (disabling UAC).
- **SmartScreen** (`security-smartscreen`): `EnabledValue = 0`, `DisabledValue = 1`. The toggle name is "Disable SmartScreen" — when the user enables this toggle, it writes `0` (disabling SmartScreen).

### Reboot Required Indication

VBS and Memory Integrity require a reboot. The `TweakPageViewModel` already shows a
`StatusMessage` and the `TweakList` control already has an `InfoBar` for messages.
We can use the `Description` field to indicate "Reboot required" for these tweaks:

```csharp
Description = "Enable Virtualization-Based Security. Reboot required.",
```

### Security Warnings

For UAC and SmartScreen, the `Description` field should include a warning:

```csharp
// UAC
Description = "Disable User Account Control. This reduces security — only disable if you understand the risks.",

// SmartScreen
Description = "Disable SmartScreen. This reduces protection against malicious apps.",
```
