# Plan 05-04: Phase 5 Gap Remediation

## Goal

Close the three FAILs and two PARTIALs from `VERIFICATION.md` (2026-10-04):
volume mixer UI (SND-02), affinity rule persistence (AFF-03), startup entry
delete (STR-03), and test-pinned DNS/NTP write paths (NET-02/NET-03).

## Requirements

| ID | Description |
|----|-------------|
| SND-02 | Volume mixer is accessible (per-device level + mute in the UI) |
| AFF-03 | Affinity rules can be saved and reapplied |
| STR-03 | A startup entry can be deleted |
| NET-02 | DNS write path pinned by tests (runtime needs elevation) |
| NET-03 | NTP write path pinned by tests (runtime needs elevation) |

## must_haves

- SND-02: Sound page shows a volume mixer (device selector, level slider, mute)
  wired to the existing `ISoundService` volume API — no dead service methods
- AFF-03: Affinity rules (process name → mask) persist across sessions and can be
  reapplied to running processes
- STR-03: Run-key entries and scheduled tasks can both be deleted (confirmed first)
- NET-02/NET-03: `SaveDnsNtpAsync` registry paths pinned by unit tests
- House rules: guard all `Toggled`/`ValueChanged`/`SelectionChanged` handlers
  against binding echo (compare to last system-read state); never touch real
  registry keys in tests (throwaway `HKCU\Software\VainTools\Test\<guid>` only);
  destructive actions behind `ConfirmAsync`

## Design

### SND-02 — Volume mixer

`SoundPageViewModel` gains `SelectedDevice`, `VolumeLevel` (0–100, for the
Slider), `IsMuted`, plus `SelectDeviceCommand` (loads `VolumeInfo` for the
device), `ApplyVolumeAsync(double)` and `ApplyMuteAsync(bool)`. A
`_lastVolumeLoaded` / `_lastMuteLoaded` pair backs `IsUserVolumeChange` /
`IsUserMuteChange` guards — the same compare-against-system-state pattern used
by `StartupViewModel.IsUserToggle` and `TweakToggleViewModel.ApplyToggle`.

`SoundPage.xaml` gains a Volume Mixer card: device `ComboBox`, `Slider`,
percent readout, mute `ToggleSwitch`. Code-behind handlers ignore binding echo.

### AFF-03 — Affinity rules

`AffinityService` persists rules under `HKCU\SOFTWARE\VainTools\AffinityRules`
(QWORD mask per process-name value), following the `StartupService` precedent
of direct `Microsoft.Win32.Registry` access. The key path is an optional
constructor parameter (default = production path) so tests use a throwaway key.
New surface: `GetRules()`, `SaveRule(name, mask)` (rejects empty name and zero
mask), `DeleteRule(name)` (throws when missing), `ApplyRules()` (reapplies to
same-named running processes, counts successes, skips failures with a log).

`AffinityViewModel` gains a `Rules` collection, `SaveRuleCommand` (current
selection + current checkbox mask), `DeleteRuleCommand` (confirmed),
`ApplyRulesCommand`; `Refresh` reloads rules. `AffinityPage.xaml` gains a Saved
Rules card with per-rule delete and one-click reapply.

### STR-03 — Delete entry

`IStartupService` gains `DeleteRunKeyEntry(entry)` (resolves the stored plain
or `-`-prefixed value in the matching non-RunOnce location, deletes it, throws
when missing) and `DeleteScheduledTaskAsync(entry, ct)` via
`schtasks.exe /Delete /TN "<folder><name>" /F`.

`StartupViewModel` gains `DeleteRunKeyEntryCommand` /
`DeleteScheduledTaskCommand`, both `ConfirmAsync`-gated, refreshing on success.
`StartupPage.xaml` gains a Delete button per row, routed through
`ElementName=StartupRoot` like the Affinity Edit button (no code-behind
needed — buttons bind commands directly, unlike toggles).

### NET-02/NET-03 — Write-path tests

`NetworkPageViewModelTests` (new): `LoadDnsNtpAsync` reads the two documented
paths; `SaveDnsNtpAsync` writes `HKLM\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters\NameServer`
and `...\W32Time\Parameters\NtpServer` with the bound values (mocked
`IRegistryTweakService`). Runtime exercise still needs elevation — covered by
the VM's try/catch + elevation `InfoBar`, documented in the summary.

## Test plan

- `StartupServiceTests`: schtasks `/Delete` arg construction (mocked runner);
  Run-key delete round-trip on a self-cleaning throwaway value (plain + `-`
  prefixed); delete-missing throws.
- `StartupViewModelTests`: delete commands confirm-gated (confirm=false → no
  service call), refresh on success, error surfaced on failure.
- `AffinityServiceTests`: rule save/get/delete round-trip on a throwaway key;
  save rejects empty name / zero mask; delete-missing throws.
- `AffinityViewModelTests`: save writes current checkbox mask for the selected
  process; apply reports the reapplied count; delete refreshes the list.
- `SoundPageViewModelTests` (new): selecting a device loads level+mute;
  volume apply converts 0–100 to 0.0–1.0; echo guard ignores programmatic sets.
- `SoundServiceTests` (new): spatial/enhancement settings mapping over a mocked
  registry (WASAPI paths stay runtime-only).
- Full gate: `dotnet build` 0/0, `dotnet test` all green, navigation smoke walk.
